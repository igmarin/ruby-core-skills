# Skill descriptions

The description helps the host choose a skill; it is not a second prompt body.

- Start with a concrete task and trigger: `Use when ...`.
- Keep the description short enough to identify the skill without copying its process or hard gates.
- Put required behavior, proof, and risk rules in `SKILL.md`, where they remain available after selection.
- Use natural punctuation. Do not force a single sentence or cram every rule into the first sentence.
- Keep project examples and long explanations in opt-in references.

Run `ruby scripts/validate-ecosystem.rb` after changing registry metadata.
